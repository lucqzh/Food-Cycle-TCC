4. PERGUNTAS QUE A BANCA PODE FAZER E COMO RESPONDER
--------------------------------------------------------------------------------

Pergunta 1: "Qual a diferença do FoodCycle para um simples CRUD de doação?"
Resposta:
"O FoodCycle não é um CRUD básico. Ele implementa uma arquitetura orientada a 
eventos com Supabase Realtime (WebSockets), Row Level Security (RLS) a nível de 
banco para proteção de dados, controle de papéis de usuários (RBAC), auditoria 
imutável e documentos legais customizados para o cumprimento da Lei 15.224/2025."

Pergunta 2: "Se o servidor do Supabase cair, o que acontece?"
Resposta:
"A aplicação Next.js foi desenvolvida com Server Components híbridos e 
mecanismos de fallback (try/catch e tratamento tolerante de erro), garantindo 
que as páginas estáticas e institucionais continuem acessíveis, enquanto as 
telas dinâmicas exibem mensagens amigáveis de reconexão."

Pergunta 3: "Como foi garantida a segurança contra acessos indevidos?"
Resposta:
"Utilizamos autenticação gerenciada via JWT pelo Supabase Auth. Além das 
verificações de rotas no Next.js (Middleware/Proxy), a segurança primária é 
garantida diretamente no banco de dados via RLS (Row Level Security), impedindo 
que uma empresa acesse doações ou solicitações de terceiros via API."

Pergunta 4: "Esses dados do Seed não vão sujar o banco de produção?"
Resposta:
"Não. Todos os registros de seed possuem CNPJs e descrições identificadas com a 
tag 'Demonstração PNCPDA TCC'. Desenvolvemos a rotina reversa de exclusão em 
cascata que limpa exatamente esses registros com um clique."
